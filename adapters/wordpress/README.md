# Адаптер WordPress

Всё, что в переезде принадлежит WordPress, а не ядру: разворачивание снимка,
внутренняя приёмка, проверка чистоты и свои грабли. Ядро (стек, смоук,
трассер, бэкап, сторож) о WordPress ничего не знает, адаптер о стеке знает
только то, что лежит в отрендеренном каталоге.

| Файл | Что делает | Фаза |
|---|---|---|
| `security-check.py` | чистота снимка до разворачивания и живого тома после | [Ф1](../../references/10-archive.md), [Ф4](../../references/40-acceptance.md) |
| `restore.sh` | идемпотентное разворачивание снимка в поднятый стек | [Ф3](../../references/30-restore.md) |
| `verify.sh` | внутренняя приёмка по эталонным числам | [Ф4](../../references/40-acceptance.md) |
| `nginx.conf` | запреты WordPress, подключаются ядром | [Ф2](../../references/20-stack.md) |
| `restore_helper.py`, `lib.sh` | общее для скриптов выше | |
| `gotchas.md` | грабли, которые принадлежат WordPress | [Ф7](../../references/70-retro.md) |
| `test_adapter.py`, `stand.sh` | юнит-тесты без докера и стенд на докере | |

## Порядок

Стек отрендерен и поднят по [Ф2](../../references/20-stack.md), трассер ядра
зелёный. Адаптер кладётся в стек каталогом `adapter/` рядом со `scripts/`:

```sh
cp -R adapters/wordpress /opt/stacks/SLUG/adapter
cd /opt/stacks/SLUG
```

**1. Снимок чист.** До разворачивания, по архиву целиком:

```sh
sha256sum snapshot.zip                    # эту сумму зафиксировать в журнале
python3 adapter/security-check.py --source archive snapshot.zip \
    --user admin:administrator --user editor:editor
```

Код 0 означает: ядро побайтово совпало с манифестом своей версии с
api.wordpress.org, в плагинах, темах и mu-plugins нет новых сигнатур
исполняемого кода, в загрузках нет PHP сверх заглушек без кода, в корне нет
чужих PHP и каталогов, пользователи в дампе ровно те, что названы. Без
`--user` проверка не проходит: сравнивать не с чем.

**2. Разворачивание.**

```sh
adapter/restore.sh --archive snapshot.zip --sha256 СУММА --old-url http://старый.адрес
```

Снимок это zip плагина бэкапа с дампом внутри его каталога установщика или
`site-files.tar.gz` из набора бэкапа ядра, тогда дамп передаётся отдельно:
`--dump database.sql.gz --dump-sha256 СУММА`. Корни старой площадки перед
`/wp-content/` скрипт находит в дампе сам и печатает. Корнем считается путь
файловой системы от двух уровней в месте, где хостинги держат сайты (`/home`,
`/var`, `/srv` и подобные); ссылка вида `/blog/wp-content/` корнем не
считается. Необычный корень передаётся `--old-path`. Если в базе другой адрес
сайта, скрипт откажется до любых изменений и назовёт его: передать
`--old-url` ровно с этим адресом.

Что делает, по порядку: сверяет сумму; распаковывает во временный каталог с
отказом на пути наружу, ссылки и особые файлы; вынимает дамп; удаляет
установщик и его остатки; генерирует `wp-config.php` из реквизитов `.env`
стека (пароль базы и соли дописываются туда один раз и дальше не меняются);
останавливает веб-сервер и приложение; заменяет том целиком и нормализует
владельца и режимы; пересоздаёт схему и пользователя базы, импортирует дамп;
правит пути и адрес, в том числе внутри сериализованных значений и в JSON;
снимает свежий дамп и ищет в нём следы старой площадки; запускает стек;
последней пишет метку разворачивания в докрут.

**Оборванный прогон перезапускается той же командой целиком.** Руками поверх
него ничего не делается. Пока метки нет, веб-сервер и приложение остановлены, и
половина сайта посетителям не отвечает. Повтор без метки разворачивает всё
заново, промежуточный каталог убитого прогона убирается под замком.

**3. Второй прогон той же командой.** Он обязан ответить «уже развёрнуто: файлы
и база не менялись» и ничего не тронуть. `--force` разворачивает заново, и
результат тоже обязан совпасть: файлы с суммами, таблицы по содержимому.

**4. Внутренняя приёмка.** Числа берутся из конца вывода `restore.sh` и
сверяются с тем, что видно на старой площадке:

```sh
adapter/verify.sh --user admin:administrator --user editor:editor \
    --published 26 --plugin forms-plugin --mu-plugins 17 \
    --old-path /home/account/public_html --old-url http://старый.адрес
```

Проверяет пользователей и роли, опубликованное, обязательные плагины на диске
и включённые, целостность всех таблиц сайта, владельца `82:82` и режимы
докрута, отсутствие кода в загрузках сверх заглушек, отсутствие установщика,
эффективные пути глазами самого приложения, отсутствие следов старой площадки
в базе и конфиге, запреты трассером с путями WordPress, ответ главной мимо
кэша.

**5. Проверка живого тома** теми же правилами, что и архива:

```sh
docker exec -u mysql SLUG-mariadb mariadb-dump --single-transaction SLUG \
    | python3 adapter/security-check.py --source volume SLUG_site_data --dump - \
        --user admin:administrator --user editor:editor
```

## Что адаптер дописывает в стек

`restore.sh` дописывает строки, а не переписывает файлы, и повтор ничего не
дублирует. Заполненное человеком не трогается.

| Файл | Строки |
|---|---|
| `nginx/adapter/wordpress.conf` | запреты из `nginx.conf`: PHP в `wp-content/uploads`, `xmlrpc.php`, `wp-config.php` |
| `backup.conf` | `exclude=wp-config.php`, `exclude=wp-content/cache`, `expect=` точки входа и ядра |
| `watchdog.conf` | `users_sql=`, `objects_sql=` с префиксом таблиц, `uploads=wp-content/uploads`, узкие `exclude=` кэша |
| `smoke/smoke.conf` | `marker=/wp-content/`, два `page=`: страница и последняя запись. `expect=` и `form_url=` не трогает: их выписывают из слепка и настроек сайта руками |
| `smoke/robots.txt.reference` | `robots.txt` из снимка, если он там был |
| `.env` | `WP_DB_USER`, `WP_DB_PASSWORD`, восемь солей |

Форму смоук не знает: `form_url=` и поля заполняются руками, либо
`form_url=none`. Трассер ядра для WordPress запускается так (его же вызывает
`verify.sh`):

```sh
scripts/verify-tracer.sh --uploads wp-content/uploads --deny /xmlrpc.php --deny /wp-config.php
```

## Своё для площадки

Узкие исключения и признаки конкретной площадки живут вне репозитория и
передаются `security-check.py --site-conf FILE`:

```
# ложное срабатывание сигнатуры, проверенное глазами по исходнику
benign=wp-content/plugins/some-plugin/vendor/lib/Parser.php|eval(
# строка в базе, законная для этого сайта
benign_sql=base64_decode(
# известные признаки прошлого заражения
ioc_md5=0123456789abcdef0123456789abcdef
ioc_domain=bad.example
# свой каталог в корне
root_entry=landing
```

## Границы

- Снимки в формате zip и tar.gz. Собственный формат архива плагина бэкапа
  (`.daf`) не поддерживается: его надо сначала выгрузить в zip.
- Одиночный сайт. Сеть сайтов не поддерживается.
- Инструмент командной строки ставится фиксированным релизом с проверкой
  суммы в отдельный образ поверх образа приложения, в работающем контейнере
  его нет.
- Для проверки ядра нужна сеть до api.wordpress.org, либо манифест файлом:
  `--core-manifest FILE`.

## Проверки адаптера

```sh
python3 adapters/wordpress/test_adapter.py      # без докера, секунды
adapters/wordpress/stand.sh                     # докер и сеть, минуты
```

Стенд собирает сайт на настоящем ядре с путями старой площадки в трёх видах,
упаковывает его в архив с установщиком и остатками, и проверяет каждое
обещание выше, включая отрицательные: чужая сумма, убитый прогон, подсаженные
пользователь и код, снятые запреты.
