# Ф2 · Стек

**Вход:** снимок принят и чист, площадка ещё не разворачивалась.
**Выход:** ядро поднято, изоляция доказана живыми пробниками.

## Зачем эта фаза

Изоляция это свойство устройства стека, а не настройка, которую добавляют потом.
Сосед по серверу не должен иметь пути к базе, а всплеск одного арендатора не должен
двигать другого. Проверяется это не чтением конфигурации, а **прорезом**: живыми
пробниками против поднятого стека.

Ядро от CMS не зависит. Всё, что принадлежит конкретной CMS, живёт в адаптере и
приезжает в [Ф3](30-restore.md), кроме запретов веб-сервера: они часть изоляции и
доказываются здесь, до того как в стек приедет сайт. Точек расширения у ядра три: запреты адаптера
в `nginx/adapter/*.conf`, строка запроса фронт-контроллера `$front_query` там же
и драйвер базы в образе приложения, общий для всех поддерживаемых CMS.

## Порядок

1. **Ни одного опубликованного порта.** Наружу смотрит только обратный прокси.
   Порт базы «на время отладки» это опубликованный порт.
2. **Четыре сети, а не три.** Docker не различает порты внутри одной сети: если
   веб-сервер и база делят хоть одну сеть, веб-сервер достаёт до базы напрямую по
   IP, в обход приложения, сколько бы правил ни было в конфигурации самого
   веб-сервера. Поэтому сеть между приложением и базой отдельная от сети между
   веб-сервером и приложением: общая с обратным прокси (снаружи), между
   веб-сервером и приложением (fastcgi), между приложением и базой, и исходящая
   только для приложения.
3. **База только в сети между приложением и базой.** Ни в общей с прокси, ни в
   сети веб-сервера, ни в исходящей.
4. **Админ базы без пароля, только по сокету.** Пароль root случаен и не известен
   никому. Разворачивание, бэкап и сторож ходят в базу учётной записью, которая
   пускает только процесс внутри контейнера базы от системного пользователя
   `mysql`, то есть `docker exec -u mysql`. Доступ к докеру и так равен root на
   сервере, новой двери это не открывает, а пароль, который пришлось бы хранить
   ради регламентных работ, становится не нужен. Приложение ходит по сети и эту
   учётку не видит. Создаётся она только на пустом томе базы; для тома, который
   уже был, порядок ручного создания записан в шапке `mariadb/initdb/`.
5. **Лимиты памяти и процессора заданы явно** каждому сервису. Без них соседа
   двигает чужой всплеск, и это видно только по чужому простою.
6. **Имена сервисов с префиксом проекта.** Система контейнеров добавляет имя
   сервиса псевдонимом в каждую сеть, к которой сервис подключён. Два одноимённых
   сервиса в общей сети дают неопределённое разрешение имени: запрос соседа может
   прийти к вам, а ваш к соседу.
7. **Доверенный адрес привязан к подсети общей сети**, а не к широкой маске. При
   широкой маске приложение примет заголовок с чужим адресом и запишет в журналы
   то, что ему передали.
8. **Запреты веб-сервера в значимом порядке.** Запрет точечных файлов ставится
   **выше** общего блока для PHP. Ниже он не работает: общий блок совпадает первым,
   и путь вида `/.secret.php` исполняется.
9. **Проверить, что общая сеть на машине существует**, до подъёма стека. Стек
   объявляет её внешней, и без неё подъём падает невнятной ошибкой про сеть.
10. **Положить запреты адаптера.** CMS известна из снимка, поэтому её запреты
   ставятся сейчас: `nginx.conf` адаптера копируется в `nginx/adapter/<cms>.conf`
   стека. Разворачивание в [Ф3](30-restore.md) перепишет тот же файл тем же
   содержимым. Загрузки у каждой CMS свои (`wp-content/uploads`, `assets/images`),
   и запрет ядра на обобщённый `/uploads/` их не накрывает.
11. **Прогнать трассер** по поднятому стеку: `scripts/verify-tracer.sh` из каталога
   стека, с ключами из README адаптера. Каталог загрузок CMS идёт ключом
   `--uploads`, свои точки входа ключом `--deny`, каталоги, где PHP обязан
   исполняться (коннекторы расширений), ключом `--allow`. Если запреты адаптера
   лежат в стеке, без `--uploads` трассер отказывается работать. Пробники
   создаются только там, где файла ещё нет, и убирается только созданное,
   поэтому трассер безопасен и на живом сайте.

## Ворота

Ворота фазы это трассер живыми пробниками. Чтение конфигурации воротами не
является ни при каких условиях.

| Что доказываем | Чем доказываем | Что записываем |
|---|---|---|
| портов нет | список работающих контейнеров с колонкой портов, она пуста | вывод целиком |
| база недостижима | попытка соединения с базой из веб-сервера и снаружи внутренней сети | отказ соединения, обе попытки |
| точечные файлы не исполняются | запрос к пробнику **с расширением `.php`**, положенному в докрут | код ответа и тело |
| PHP в загрузках CMS не исполняется | пробник `.php` в каталоге загрузок из адаптера: трассер с `--uploads` этого каталога | путь пробника, код ответа и тело |
| точки входа расширений исполняются | пробник в каталоге, который адаптер оставляет открытым: трассер с `--allow` | путь и тело с отметкой исполнения; для CMS без таких каталогов «нет» с причиной |
| короткого псевдонима в общей сети нет | разрешение короткого имени изнутри общей сети не даёт ваш сервис | вывод разрешения имени |
| лимиты заданы | инспекция контейнеров показывает ненулевые лимиты | значения по каждому сервису |

**Пробник обязан иметь расширение `.php`.** Запрет на чтение файла срабатывает там,
где запрет на исполнение не срабатывает, и первая версия такой проверки была
зелёной при открытой дыре именно потому, что пробник расширения не имел.

**Не считается прохождением:** «в описании стека портов нет»; проверка синтаксиса
конфигурации; пробник без расширения; пробник в обобщённом `/uploads/` ядра, когда
у CMS загрузки лежат в другом месте; проверка, которая ни разу ни на чём не падала.
Проверка без доказанного отрицательного результата не гарантирует ничего: подсадите
нарушение и убедитесь, что трассер его находит.

## Чего не делать

- Не публиковать порт базы, даже временно, даже на адрес обратной петли.
- Не подключать базу к общей сети «чтобы удобнее было смотреть».
- Не давать сервису короткое имя вида `web` или `db`.
- Не ставить запрет точечных файлов ниже общего блока для PHP.
- Не считать запрет на загрузки доказанным по пробнику в чужом каталоге: путь
  загрузок принадлежит CMS.
- Не принимать трассер, который никогда никого не ловил.
- Не разворачивать сайт в непринятый стек: [Ф3](30-restore.md) начинается после ворот.
