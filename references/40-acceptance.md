# Ф4 · Приёмка

**Вход:** сайт развёрнут, доступен на временном адресе, внешняя проверка не проводилась.
**Выход:** три источника доказательств зелёные, заявка доставлена человеку.

## Зачем эта фаза

Эти ворота стоят перед единственным шагом, который видят посетители. Всё, что не
поймано здесь, ловит клиент заказчика.

Отказы в этой области молчаливые, поэтому доказательств три, и они смотрят с разных
сторон. Снаружи видно не то, что видно изнутри, а скан безопасности не видит ни
того, ни другого. **Зелёная проверка без взгляда глазами приёмкой не считается.**

## Порядок

1. **Снаружи, чёрным ящиком, по настоящему имени хоста.** Имя подменяется в
   разрешении имён локально, домен при этом не трогается. По адресу вместо имени
   проверять нельзя: имя хоста участвует в маршрутизации запроса и в генерации
   ссылок. Инструмент: `smoke/smoke.sh --resolve IP` из каталога стека, конфиг
   площадки в `smoke/smoke.conf`. Проверки публичного имени (сертификат, `www`,
   переход на https) в этом режиме печатаются как отложенные и на код не
   влияют: зелёный прогон доказывает сервер, а не переключение. Смоуку верят
   только после зелёного `smoke/selftest/run.sh`.
2. **Сравнивать тела страниц, а не только коды.** Взять набор разных адресов и
   убедиться, что тела **различаются**. Совпадение тел у разных адресов это признак
   оборванного восстановления, при котором каждый адрес рендерит главную и всё
   выглядит исправным по кодам.
   Тела, различающиеся между собой, ещё не значат, что это тот же сайт: кодировка,
   ставшая вопросами, портит все страницы одинаково. Поэтому в `smoke.conf`
   выписываются `expect=`: адрес и буквальный текст, который был на нём в слепке
   старой площадки, лучше с кириллицей. Слепка нет совсем: `expect=none`, и
   причина пишется в отчёт фазы. Туда же смотрит проверка ссылок на внутренние
   адреса: CMS, выводящая адрес сайта из имени хоста запроса, после проверки с
   чужим именем кладёт в кэш ссылки на `127.0.0.1` или имя контейнера.
3. **Проверить медиа глазами и грепом.** Источник с ведущим слэшем даёт адреса
   вида `//assets/...`, браузер читает это как имя хоста, и картинки не грузятся
   при полностью зелёной странице. Искать в выданном HTML ссылки, начинающиеся с
   двойного слэша.
4. **Сделать запрос мимо статического кэша.** Живой кэш способен отдавать 200
   поверх мёртвого приложения неделями. Запрос в обход кэша обязан отвечать 200,
   а не 500.
5. **Изнутри проверить то, что снаружи принципиально не видно:** счётчики ключевых
   таблиц против эталона из [Ф3](30-restore.md), проверку целостности таблиц,
   владельца и режимы докрута, отсутствие исполняемого кода в каталогах загрузок.
   Эталоны счётчиков для конкретной CMS даёт адаптер.
   Адаптер WordPress: [`verify.sh`](../adapters/wordpress/README.md).
   Адаптер MODX: [`verify.sh`](../adapters/modx/README.md), он сравнивает тела
   страниц, а не только коды.
6. **Прогнать скан безопасности по живому сайту**, не по копии.
7. **Выписать получателей заявок.** Полный список адресов по каждой форме из
   настроек снимка: системные настройки, настройки расширения формы, скрытые
   копии. Показать список владельцу сайта и получить подтверждение; адрес
   подрядчика или бывшего сотрудника убрать до проверки доставки, со сбросом
   кэша настроек. Правка в базе без сброса кэша оставляет письма старым
   получателям.
8. **Доказать доставку заявки.** Отправить форму и найти письмо во входящих у
   **каждого** получателя из подтверждённого списка. Плагин формы в бесплатной редакции может не хранить заявки вовсе:
   письмо тогда единственный носитель обращения, и сбой почты теряет заявку молча,
   показывая посетителю «успешно».

## Ворота

| Что доказываем | Чем доказываем | Что записываем |
|---|---|---|
| сайт отвечает как сайт | внешний смоук по имени хоста со сравнением тел между собой | число проверенных адресов и число различных тел |
| сайт отвечает как старый | текст из слепка старой площадки найден буквально на тех же адресах: `expect=` смоука, в том числе строки с кириллицей | пары «адрес, текст» и результат по каждой; при `expect=none` причина, почему слепка нет |
| ссылки ведут на сайт | в телах нет абсолютных ссылок на внутренние адреса и имена контейнеров | результат проверки смоука |
| страница не притворяется | проверка медиа глазами плюс поиск ссылок с двойным слэшем | снимок экрана и результат поиска |
| приложение живо | запрос мимо кэша | код ответа и путь запроса |
| данные на месте | счётчики ключевых таблиц против эталона | числа по каждой таблице, обе стороны |
| докрут в порядке | владелец, режимы, отсутствие исполняемого кода в загрузках | значения и пустой список находок |
| скан пройден | скан безопасности по живому | отчёт и разбор находок |
| получатели заявок те, что надо | полный список получателей каждой формы выписан из настроек снимка и подтверждён владельцем сайта; лишний адрес убран до проверки | список «форма, получатели» и кто подтвердил |
| заявка дошла до человека | письмо найдено во входящих **каждого** получателя из подтверждённого списка | тема, время, адресат по каждому; содержимое не нужно |

**Не считается прохождением:** коды ответа без сравнения тел; тела, которые
различаются между собой, но не сверены со слепком старой площадки; «форма показала
сообщение об успехе»; запись в журнале отправки вместо найденного письма; письмо у
одного получателя, когда получателей в настройках несколько; скан по копии;
зелёный отчёт, который никто не открывал глазами.

## Чего не делать

- Не принимать сайт по кодам ответа.
- Не проверять по адресу вместо имени хоста.
- Не откладывать найденное на «после переключения»: после переключения это видят
  посетители.
- Не переходить к [Ф5](50-cutover.md), пока хотя бы одна строка ворот пуста.
- Не сбрасывать и не инвалидировать живой статический кэш на старой площадке ради
  чистоты проверки. Запрос мимо кэша проверяется на новом стенде; на старой
  площадке сброс необратим и снимает последнее, что ещё отдаётся посетителям, см.
  [Ф1](10-archive.md).
